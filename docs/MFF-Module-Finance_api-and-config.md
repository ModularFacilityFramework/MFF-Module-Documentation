# Finance module: API, files and configuration

Module `finance`, mounted at /api/finance. Reads need the page (coreApi.requirePage); writes also need developer/administrator/facility_manager/facility_staff; deletes need developer/administrator/facility_manager (GPU purchases, as in the old app, are writable by those three only; facility profiles are created/edited by manager+ and deleted by administrator/developer only). Needs mff-core 0.1.185 or newer (shared DrillDownPie).

## Configuration and dependencies
- MODULE_FINANCE_FILES_DIR in mff-core's App_backend/.env (read via coreApi.getModuleConfig().FILES_DIR; declared, as documentation only, in the manifest `config` array). Optional: the default is /home/local/nusbf/MFF-core/module-finance/files (the MFF data disk, beside core's per-user workspaces); the backend user must be able to write there. Layout: one sub-folder per REQ number (REQ123/<file name>); inbox/ holds PDFs dropped by the email process (PurchReq_<x>_REQ123.pdf = the REQ, REQ123_<name> = its attachments); _deleted/ receives the files of a deleted REQ (moved, never erased). Files are served only by GET /spending/requisitions/:id/files/:fileId, which needs login, the spending page and one of developer/administrator/facility_manager/facility_staff. Rows migrated from the old app keep their old absolute file_path; if it is outside the folder the file is found as <folder>/<REQ number>/<file name>, so copying the old uploads/requisitions/ tree into the folder is enough.
- npm dependencies installed with the module: exceljs (SAP .xlsx), multer (uploads), pdf-parse (REQ PDF text). Routes load them lazily.

## Endpoints (all under /api/finance)
- Years/people: GET /years (ordered by start_date ascending; each year also carries frozen, frozen_at, frozen_by; hidden years are never listed), GET /people -> { users, pi_ids }: `users` sorted by first name, then last name (case-insensitive), each with `job_position` and `is_pi` (`is_pi` is absent on a core older than 0.1.199); `pi_ids` as before. Freezing: PUT /years/:id/freeze and PUT /years/:id/unfreeze (developer, administrator, facility_manager), GET /years/:id/freeze-log. Every write/remove route answers 423 with a message when it would change a frozen year (see the overview, "Frozen years").
- Costing (page costing_model): GET /costing/year/:yearId (services, salary, nonSalary, depreciation, spaceTypes, rooms, derived rates, and a `totals` object; totals are the exact sum rounded once, not the sum of rounded rows); CRUD for services (+reorder), salary, non-salary, depreciation, rooms, space types. Allocations are sent as percent per service id: rooms must total exactly 100, other kinds at most 100. Depreciation of a year is computed from the year's own dates (the old app used today's date). Deleting the last service of a year, a service used by PhD entries or grants, or a space type used by rooms answers 409.
- Recovery (page recovery): GET /recovery/year/:yearId; POST /recovery/year/:yearId/entries; PUT/DELETE /recovery/entries/:id. Recovered quantity = sum of entry quantities; GBP recovered = quantity x (service cost / service quantity); % = recovered / service quantity (may exceed 100).
- Grants (page grants): GET /grants/year/:yearId (gpu, phd derived from the EM IT recovery entries, grants); POST /grants; PUT/DELETE /grants/:id; PUT /grants/:id/status (costed|active|archived); GPU allocation lines: POST /grants/year/:yearId/gpu, PUT/DELETE /grants/gpu/:id, body { group_id, quantity, start_date, end_date?, pi_user_id?, notes? } (start_date and group_id are required; dates inclusive, end_date empty = open-ended); writes are manager-only (developer, administrator, facility_manager) and a frozen year refuses them (423); reading is never stopped by a freeze. A grant costed in year Y is active from year Y+1 for length_years years.
- GPU allocations lookup, for other modules (for example slurm): GET /gpu-allocations[?date=YYYY-MM-DD][&groupId=N]. Roles developer/administrator/facility_manager/facility_staff; page `grants` (core skips the page check for a callModuleAsUser call). Response: `{ schema: 1, generatedAt, date, lines: [{ id, groupId, groupName, groupNameKnown, gpus, startDate, endDate, active, datesAssumed, label (always null), piUserId, notes }], groups: [{ groupId, groupName, activeGpus, activeLines, lines }] }`. `lines` = every line of every visible (non-hidden) year, optionally of one group. `groups` = one entry per group that has a line, with the GPUs active on `date` (default today, the server's local day), overlapping lines added up; a group with only expired or future lines totals 0; a line with no group has groupId null. `groupName` is the group's current name, read with coreApi.listGroups() (mff-core 0.1.197 or newer). While the running core cannot list groups, `groupName` reads "Group #<id>" and `groupNameKnown` is false; it is never null for a real group. A line with no group has `groupId` null and `groupName` null. Errors: non-2xx with `{ success: false, message }`.
- Spending (page spending): transactions GET /spending/year/:yearId/transactions, PUT /spending/transactions/:id (costing item, MX/EM, notes), PUT .../:id/toggle-exclude (409 if reconciled), POST /spending/year/:yearId/transactions/import (multipart `file`, SAP .xlsx; only rows posted inside the year are imported; hash = md5 of cost element|company|name|posting date|value, a genuinely identical second line in the same file is kept with a suffix). Rules: GET/POST /spending/year/:yearId/rules, PUT/DELETE /spending/rules/:id, POST .../rules/apply (only touches unreconciled transactions; field in name|cost_element_name|company|po|cost_element, operator contains|starts_with|ends_with|equals, case-insensitive; later rules win). Reconcile: GET /spending/year/:yearId/reconcile, .../reconcile/suggestions/:po, .../reconciled; POST .../reconcile ({po_number or transaction_ids, req_id, notes}); PUT /spending/reconcile/:id/req (change or remove the REQ); DELETE /spending/reconcile/:id (undo). One PO has one REQ, one REQ can serve many POs; a PO already reconciled in another year gets the new transactions attached to its reconciliation. Summary: GET /spending/year/:yearId/summary (EM/MX figures count reconciled transactions only; credits are negative values; excluded rows count nowhere).
- Requisitions (page spending): GET /spending/year/:yearId/requisitions, GET /spending/requisitions/:id, GET .../:id/files/:fileId (the stored file), PUT .../:id (notes, pre-approved by, vendor count), PUT .../:id/toggle-exclude, DELETE .../:id (409 if linked to a PO), POST .../:id/split-by-vendor (one copy per vendor; the original is hidden from the reconcile picker while copies exist), POST /spending/requisitions/import (multipart req_pdf + attachments, ?action=replace|add_files after a 409 duplicate; the year is the one containing the REQ's date), GET /spending/requisitions-inbox, POST /spending/requisitions-inbox/process.
- Quotes (page quotes): GET /quotes/year/:yearId, GET /quotes/year/:yearId/services-with-rates, POST /quotes/year/:yearId, GET/PUT/DELETE /quotes/:id (PUT/DELETE draft only), PUT /quotes/:id/status (draft|sent|pending|paid|cancelled; no way back to draft; a quote without lines cannot leave draft), GET /quotes/:id/print (escaped HTML page, no scripts, CSP; the browser prints or saves it as PDF - no puppeteer). Number Q-<calendar year>-NN. Totals: line = quantity x unit price (2 dp), VAT only on VAT lines, default 20 %. Facility profiles: GET/POST /facility-profiles, PUT /facility-profiles/:id, PUT .../:id/default, DELETE .../:id. Logo upload is not supported.
- Reports & Stats (page reports_stats): GET /stats/year/:yearId/:chart[?parent=<slice key>] -> { success, data: [{key,name,value}] } for the shared DrillDownPie. Charts: spend-by-service, spend-by-category, spend-by-supplier (top 15 + Other), cost-by-service, recovered-by-funder, quotes-by-status, grants-by-funder.
